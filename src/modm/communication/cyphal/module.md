# Cyphal Node

`modm::cyphal::Node<Can>` is a `modm::canard::Node<Can>` of the `modm:ext:libcanard`
module with the standard services of the `uavcan.node` and `uavcan.register`
namespaces, which tools like Yakut expect from a Cyphal node:

- `uavcan.node.Heartbeat` once per second, with `setHealth()`, `setMode()` and
  `setVendorStatus()`.
- `uavcan.node.GetInfo` with the name, versions and unique ID of `NodeInfo`.
- `uavcan.node.ExecuteCommand` with `COMMAND_RESTART` (if a restart function is
  configured), `COMMAND_STORE_PERSISTENT_STATES` and `COMMAND_FACTORY_RESET`.
- `uavcan.register.Access` and `List` for the parameters.

The data types are generated by the `modm:ext:nunavut` module.

```cpp
#include <modm/communication/cyphal.hpp>

// 65535 is "unset" by convention, the node then picks a free node-ID
modm::canard::Parameter node_id{"uavcan.node.id", 65535, 0, 65535};
modm::canard::Parameter gain{"example.gain", 0.5f, 0.f, 10.f};
modm::canard::Parameter* const parameters[]{&node_id, &gain};

modm::cyphal::Node<Fdcan1> node;

std::array<uint8_t, 16> unique_id{};
// e.g. the UID of the device, see modm::platform::getUniqueId()
node.initialize({.name = "io.modm.example", .unique_id = unique_id, .software_major = 1},
                {.node_id = node_id.integer() <= 127 ? uint8_t(node_id.integer()) : CANARD_NODE_ID_ANONYMOUS,
                 .parameters = parameters, .restart = [] { NVIC_SystemReset(); }});

while (true)
{
    node.update();
    // canard_publish_13b() etc. on node.canard with the nunavut data types
}
```

The services answer in `update()`, which must be called every few
milliseconds. It needs about 1.5 kB of stack for the register responses, which
are encoded on the stack.

Without node-ID, libcanard picks a free one and moves to another one when it
detects a collision, as Cyphal v1.1 does instead of the plug-and-play node-ID
allocation of v1.0, which needs anonymous frames that libcanard v5 cannot send.

The `uavcan.node.port.List` message is not published: its serialization
buffer has more than 8 kB.


## Registers

The register services read and write the `modm::canard::Parameter`s of the
node by name, and List returns their names by their index in the `parameters`
span. An integer parameter is an `integer64`, a real one a `real32` and a
boolean one a `bit` register with one element, also for standard registers
like `uavcan.node.id`, which the specification defines as `natural16`. A write
with one element of any integer or natural type is converted, for real
parameters also of any real type, and for boolean ones only 0 and 1. A write
with another type, more elements or a value out of range is refused, and the
response contains the current value. Registers are mutable, and persistent if
the node has a storage.

A request that arrives while the previous request of the same service is
still unanswered is dropped. This only affects clients that send several
requests at once, the node answers within the next `update()`.

`COMMAND_STORE_PERSISTENT_STATES` saves the parameters to the
`canard::ParameterStorage` (without storage the command is refused), and
`COMMAND_FACTORY_RESET` removes them from it and resets them to their defaults.
Like other changed registers, the defaults take effect after a restart, e.g.
for the node-ID. `node.save()` and `node.erase()` do the same
from the application. See the `modm:ext:libcanard` module for the parameters and
their storage.
